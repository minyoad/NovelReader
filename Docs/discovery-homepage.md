# 缓存与聚合发现首页

## 本轮行为

- 进入「发现」先展示上次保存的书籍。缓存不足或超过 10 分钟时，在保留现有卡片的同时后台更新；刷新失败也保留可浏览内容。
- 自动模式每次只请求 3 个来源，可在「发现来源」指定最多 5 个。每个来源取一个分类的第一页，优先近期可用、响应较快的来源，结果先返回先展示。
- 同名、同已知作者合并为一张卡片，保留所有来源与版本。未知作者不会仅凭同名跨来源合并。可从每张卡片的来源菜单选择其他版本；已在书架的书可直接打开原书。
- 每批最多 20 本。「换一批」优先使用缓存池未展示的候选；有候选时无需等待慢来源。池内候选用完后，再轮换来源/分类请求；没有新内容时保留现有内容，必要时轮换已有候选。
- 默认优先推荐/精选/热门等分类，但不假设不同书源有统一分类格式；仍保留「按书源浏览」入口。
- 进入首页及单书源浏览均不再自动检测全部书源；全量检测仅从单书源选择器中手动发起，离开时停止。

## 请求和缓存边界

- 发现专用 HTTP 客户端：请求超时最多 6 秒，资源超时 6 秒，不自动重试；一次响应超过 2 MiB 不再解析。这个预算针对 HTTP，请求完成后的解析仍可能额外耗时。
- 每个来源最多提取 40 条列表项，缓存池最多保留 300 条来源记录，并截短过长简介等展示字段。封面、详情、试读与阅读仍通过原有流程加载。
- 取消更新、离开页面、切换配置时取消旧任务。取消不是失败，不会触发来源冷却，也不会把它自动停用或删除。
- 真正失败只暂时冷却 5～30 分钟；手动刷新可忽略冷却重试。聚合首页不沿用旧版永久隐藏判定，避免临时网络错误让来源永远消失。
- 本地 `discovery-feed.json` 保存候选、当前批次、来源选择和近期表现，不加入跨设备同步。
- 停用、删除、修改规则后，相应缓存失效。较旧的异步保存不能覆盖较新的批次或偏好；保存顺序保留亚秒精度。
- 最近表现衡量的是发现列表，不能保证对应正文一定可读；有其他来源时保留选择入口。

## 验证

- 新增 7 个引擎测试：保守去重与版本保留、来源优先级、均衡分批与不重复、短期冷却与最多五源、来源配置变化使缓存失效、缓存跨实例恢复及同秒旧保存保护、先到先展示、取消不产生失败判定。
- `swift test --skip TextDecodingTests`：71 项 XCTest 与 341 项 Swift Testing 测试通过，共 412 项。编码组是前一轮已在基线复现失败的 GBK 测试，本轮未改动编码实现。
- 新增 3 个 iOS 条件测试，覆盖缓存不联网、缓存换批、更新失败保留卡片及停止更新；这些 UIKit 条件测试未在 Linux 执行。
- 使用去除 SwiftUI 观察包装的同一模型代码，在 Linux 进行类型检查与缓存/离线逻辑运行检查。它不能替代 SwiftUI 属性包装、界面或 iOS SDK 的实际验证。
- Swift 前端语法检查与 `git diff --check` 通过。iOS 构建、真机网络超时与界面验收仍待执行。

真机重点检查：首次无缓存、多来源一快一慢、断网有缓存、连续换批、切换来源、刷新中离开返回、停用或修改书源、不同作者同名书、同书多来源与已在书架、单书源浏览和主动全量检测。
