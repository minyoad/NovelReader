# 阅读体验分析与本次优化

## 项目结构

- `NovelKit`：书源解析、网络、缓存、字符坐标转换、AI、TTS 和同步，可独立于界面测试。
- `NovelReader`：SwiftUI 界面；`ReaderModel` 协调加载、进度和朗读，`PagedReader` 使用 CoreText 分页，`ReaderContent` 提供滚动阅读。
- 已有优势：预缓存、主题和字体配置、基于原文字符偏移的进度、朗读跟随、离线示例和引擎测试。

## 本次发现与修复

| 问题 | 原因 | 修改后的行为 |
| --- | --- | --- |
| 滚动阅读退出后丢失位置，重新朗读也可能从旧位置开始 | 只更新章节进度条，没有同步字符偏移和持久化进度 | 用户滚动后保存首个可见段落的原文起点；同一段落不重复写入 |
| 长短段落混排时恢复位置偏差大 | 用字符比例乘段落数来猜测段落 | 共用 PaginatedText 的原文偏移，直接定位对应段落，恢复到顶部 |
| 切到新章节可能保留旧滚动位置 | 偏移为零时恢复函数直接返回 | 零偏移也定位首段；末尾进入的请求定位末段 |
| 重复句子导致朗读高亮跑到前面 | 搜索句子前十二个字的第一次出现 | 使用朗读控制器计算的原文偏移定位段落 |
| 快速连续切章时可能出现标题与正文不一致 | 多个异步请求完成顺序与用户操作顺序不同 | 只有最新请求可更新正文、错误和朗读；关闭阅读器使在途请求失效 |
| 切章等待时进度条还显示上一章进度 | 没有重置章节进度 | 开始加载时重置，并停止旧章预取和清理队列 |

## 验证情况

- 新增 Swift Testing 测试：不等长段落、空白行、重复内容、Emoji、负偏移、越界偏移和空正文。
- `git diff --check` 通过。
- 当前执行环境没有 `swift` 命令，`swift test` 无法启动；也没有执行 iOS 构建或真机测试。新增测试尚未运行。

具备 Swift 工具链后运行 `swift test`；具备 iOS SDK 和 xtool 后运行 `xtool dev build`。

## 真机验收建议

1. 滚动到示例章节中间，退出再进入，检查是否回到刚才的段落；切到分页模式后检查位置。
2. 在长短段落混排的章节恢复进度，确认不再按段落比例跳位。当前保存精度为段落级，长段落会从段首恢复。
3. 连续快速跳转多个章节，在慢速网络下检查最终标题、正文和进度始终属于最后一次选择；加载期间退出后不应重启朗读。
4. 用包含重复句子的章节朗读，检查高亮与自动滚动是否跟随正确的段落。
5. 检查手动滚动、程序恢复、暂停和继续朗读、字号变化、主题变化与前后台切换。

## 后续优化方向

- 超长章节：评估逐段 GeometryReader 和普通 VStack 的布局成本，再决定是否引入带位置索引的懒加载或统一 UIKit 文本视图。
- 排版一致性：滚动模式仍以 SwiftUI Text 和全角空格缩进，无法完全复现 CoreText 的首行缩进和两端对齐；统一文本渲染可同时提升精度与位置恢复粒度。
- AI 整理、换源与刷新目录：进一步覆盖这些异步操作与切章交错时的状态一致性。
- 加载状态与无障碍：在 iOS 上补充界面测试，验证 VoiceOver、字号放大、Reduce Motion 和窄屏控件布局。

本次修改保留现有主题与翻页交互，集中改善阅读连续性。
