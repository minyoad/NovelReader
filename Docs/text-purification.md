# 本书文本净化与书架进度

书架卡片显示「未读」或「约 X% · 当前章/总章数」以及进度条。只读取本地目录；目录未下载时显示读至第几章。百分比按章节等权估算，当前章有缓存时结合已读字符位置计算，章节长短不均时不等于全书字数百分比。更新目录会改变分母。

阅读时轻点正文唤出工具栏，点右上角「更多（…）→ 文本净化」即可设置（试读需先加入书架）。也可从书架长按一本书 →「文本净化」，或进入「书籍信息 → 本书文本净化」。规则按本书 ID 存在本机 `text-purification.json`，不参与当前跨设备同步；不同书籍互不影响。换源保持同一本书 ID 时沿用规则。

- 打开启用开关，添加普通文本或正则表达式规则。
- 替换内容留空表示删除；正则支持 `$1` 等捕获组，普通文本中的 `$` 和标点按原样处理。
- 例如 `(?m)^广告.*\n?` 删除以「广告」开头的整行；`(?s)` 可让点号跨行匹配。
- 使用编辑按钮排序或删除规则；每本书最多 50 条。
- 预览优先载入当前章节缓存前 20000 字，也可粘贴测试文本；预览不会修改正文。保存前检查已启用规则语法。

净化是显示与朗读层的转换：当前正文、邻章分页预览、朗读预取使用同一规则。缓存和 AI 整理输入不写入正则替换结果，关闭规则后恢复未净化文本。AI 整理和还原操作仍处理其原有的缓存数据。阅读期间保存规则会停止朗读，清理旧的朗读预取，重新排版本章并回到章首；邻章分页缓存包含净化版本标识。

执行限制：单次处理总预算约 100ms（依赖正则引擎的进度回调），最多 10000 次匹配、输入/输出最多 200 万 UTF-16 单元、每条匹配和替换配置最多 2048 字符。遇到耗时或超大规则保留该规则之前的文本；预览显示警告。限制并非隔离进程的硬实时保证。

验证：8 项核心测试覆盖普通文本特殊字符、捕获组、多行删除、顺序和停用、非法规则、过量匹配、病态表达式的中断、按书持久化与保留正文、进度边界。Linux 无法完成 iOS 界面构建及真机阅读/朗读验收。
