# 分页模式跨章优化

## 代码中确认的停顿来源

1. 跨章没有普通翻页的落页动画：释放手势后停住旧页，等待取回正文再直接替换。
2. `PagedReader.paginate` 在主线程同步调用 CoreText，对新章节做整章分页，下载缓存并不能省去这部分计算。
3. 页面绘制层每次接收相同纸色仍调用 `setNeedsDisplay`；拖动中的视图更新会反复触发 CoreText 绘制。
4. 每次构造视图的排版键都会计算整章字符串哈希；分页过程中也会为每页从头换算字符坐标来判断段首。

以上结论来自代码分析，尚未通过 Instruments 或真机帧率测量。

## 修改

- 阅读当前章节期间，提前准备下一章和上一章的分页。布局缓存最多保留当前章与相邻两章，按正文、尺寸、字体、行距、主题等配置校验。
- 相邻章节准备好后，手势直接揭开下一章首页或上一章末页，并继续使用覆盖、淡入或仿真翻页效果；动画完成后提交章节切换，避免中途换掉正在移动的页面。
- 未准备好的章节仍保留当前页面和加载反馈，不保证消除网络等待。
- CoreText 分页在后台队列计算；新内容、字号变化、旋转或离开阅读器时，过期结果不会安装到界面。
- 正文哈希仅在内容变化时计算；分页用 UTF-16 前一字符判断段首，避免逐页重复遍历整章字符。
- 相同纸色不再触发重绘；重新排版后清理旧的页面样式缓存，避免复用旧字体或旧正文。
- 翻页动画期间暂停朗读驱动的页面跳转；旧动画完成回调不能覆盖新的章节或布局。

## 验证与限制

- `git diff --check` 通过。
- 使用 tree-sitter 对阅读器目录、Package.swift 与新增分页测试执行语法解析（11 个文件），无语法解析错误。这不能替代 Swift 编译和类型检查。
- 新增 iOS 条件测试，覆盖长章节的 Unicode 正文完整性、段首标记、绘制切片和窗口尺寸变化。
- 当前环境没有 Swift 工具链与 iOS SDK，因此没有运行 Swift 测试、iOS 构建或实际帧率测试。

## iOS 验收

1. 使用三个翻页效果，连续跨到下一章，再反向退回上一章末页，检查正文衔接与页码。
2. 最后一章向前、第一章向后滑动，以及未达到翻页阈值后松手，均应正常回弹。
3. 断网测试已缓存章与未缓存章；加载失败后应可重试，界面不能一直锁住。
4. 在预排版期间调整字号、行距、主题和屏幕方向，检查最终布局符合新设置。
5. 加载或动画期间关闭阅读器、从目录跳章，检查旧请求与旧动画不会影响新位置。
6. 用 Instruments 对长章跨章录制主线程与帧率，确认分页计算已不在主线程执行，并测量优化前后掉帧情况。
