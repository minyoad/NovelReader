# 同步进度确认

## 原机制与问题

- WebDAV、S3 共用 SyncService，先读远端再合并；进度按 `updatedAt` 选择较新记录。
- 原触发点为启动、后台和手动同步；同步合并后只刷新书架，没有让已打开的 ReaderModel 接收跳转决定。
- 原流程在上传前写本地；上传失败时，本地已经消耗了远端进度，下次重试可能无法再识别这次变化。
- 不同设备独立添加同一本书时，合并记录有机会带入远端 UUID，影响本机缓存和阅读器引用。

## 本次行为

- 增加回到前台的同步，保留已有的同步并发保护。
- 沿用按更新时间选择进度的规则；仅当成功同步实际采纳的同一本、同书源进度更靠后时，产生确认请求。先比较章节索引，再比较同章字符偏移；更新时间变化、同位置、倒退、远端新增书籍或不可比较的书源变化不弹窗。
- 弹窗显示书名、本地章节与章内字符位置、远端章节与章内字符位置，提供「保持本地位置」「跳转到远端进度」。
- 优先询问正在阅读的书；没有打开阅读器时，询问本地最近阅读的书。其他待确认的书在打开时询问，避免连续弹出整架书的对话框。
- 启动自动恢复与普通打开都会先保留待确认的本地位置；后台完成时等待回到前台再展示。待确认记录仅存本机，不随同步文件传播，进程重启后仍会恢复。
- 确认跳转时停止原朗读队列，按章节标题或索引定位，必要时刷新目录，并恢复章内偏移；同一章正文不变时也会触发重新定位。分页跳到相应页，滚动跳到相应段落。
- 保持本地位置会保存本地当前位置和新的更新时间；未出现新的远端变化时不重复询问。同一位置或本地已追上远端时，取消过期请求。
- 询问期间，分页恢复和朗读回调只更新待确认的本地位置，不会提前覆盖同步得到的远端位置。

## 同步可靠性调整

- 远端网络读取之后才取本地合并快照，纳入读取期间的阅读进度。
- 上传成功后才落盘合并数据；上传失败保留原本地状态及下次成功同步时的提示机会。
- 同步完成重载书架时保留同步期间更新、且时间更新的本地阅读进度。
- 跨设备同书去重保留本机书籍 ID。
- 新同步或换源使旧候选失效时，不再使用旧候选跳转。

## 检查与限制

- 新增引擎测试：章节与同章偏移比较、相同位置与倒退、旧时间戳、不同书源、远端独有书籍、跨设备 UUID、上传失败、重复同步及待确认记录恢复。
- 新增 iOS 条件测试：打开时保留本地位置、保持本地、接受远端偏移、一次性处理决定。
- `git diff --check` 通过；修改文件做了 Swift 语法解析比对。AppModel 原搜索代码存在 tree-sitter 解析兼容性问题，比对基线没有新增解析错误。
- 当前环境缺少 Swift 工具链和 iOS SDK，新增测试尚未运行，也未进行 Swift 类型检查或真机测试。

真机需检查：WebDAV/S3 分别跨设备推进章节与同章位置；前后台及重启；启动自动恢复；确认与取消；分页/滚动/朗读；慢网络期间继续阅读；上传失败后重试；当前书与其他书同时更新。
